# Changelog

## Unreleased

### Added
- **The picture MXF is written while the encode runs**: a GUI build hands each finished codestream straight to the wrapper instead of encoding the whole picture, then reading the J2K directory back to wrap it, so packaging no longer pays for a second pass over the essence. The MXF is the same file either way, byte for byte, which is what postkit's overlapped wrap is tested against. One predicate decides it before the encode starts, and the job log names the reason when the answer is no: a held still, an image or J2K sequence, a head or tail trim, 3D, head/tail padding, a split composition, `--versions` and `--encrypt` all take the encode-then-wrap path unchanged, the last because the picture content key is minted while the package is written. A cancel or a failure on either side deletes the part-written MXF and leaves the codestreams that finished, so a resumed build still has them. `create` on the command line is unchanged: it encodes through the resumable encoder, which writes codestreams and has no frame feed for a wrap to read
- **A playlist that plays packages one after another**: the preview area gained a queue under the scrubber, and a package reaches it from the `+` on a Recent Projects row or the Queue button beside a finished build. A row shows its position and title, moves up or down, comes out, and plays the queue from wherever it is clicked, the row playing carrying a marker and taking the composition title mpv reports once the package is loaded. When a package reaches its last frame the next row loads and starts on its own, off the `eof` the metadata poll now carries rather than a timer of its own. A row plays through the same `previewPackage` the Play button uses, so a queued package arrives with its packaged subtitle and caption tracks attached and the crop overlay cleared, rather than with the crop of whatever was previewed before it still drawn over the frame. Previewing anything else, from the toolbar or a reel's picture, leaves the rows where they are and stops any end of file advancing them until a row is clicked again. The queue lasts the session: nothing is written down and there is no playlist file. Shared with imfwizard through the guikit submodule.
- **The Recent Projects panel starts out of the way**: the panel is collapsed on first run and the header toggles it, with the last state kept in localStorage, so a long list of packages no longer pushes the Assets panel down the moment the app opens. The rows, the retitle and the delete are unchanged.
- **TMS upload**: `tms <package-dir>` puts every file of a finished package into `<path>/<package dir name>/` on a theatre management system over sftp or ftp, and `create --upload-to-tms` does it straight after a successful build, before `--shutdown-when-done` powers the machine off. The protocol, host, optional port, remote path, user and password come from a TOML file, `~/.config/dcpwizard/tms.toml` unless `--tms-config` points elsewhere, read the way `--smtp-config` is: the password is redacted in Debug, never logged, never echoed in an error and never passed as a command-line argument. Remote directories are created before the files that go in them, each file logs an `[n/total] Uploaded` line, and the first failure stops the upload naming the file and the remote path it was going to rather than leaving a half package with a success. An unreadable config fails before the encode starts instead of an hour later. An sftp host is checked against `~/.ssh/known_hosts` and refused when its key is unknown or has changed, with the fingerprint and the `ssh-keyscan` line that would record it, since libssh2 checks no host key by itself and an unchecked upload hands the TMS password to whatever answers on the address. Plain ftp sends the login and the package unencrypted and says so, so sftp is the protocol to use wherever the TMS offers it
- **A library of head idents, tail idents, rating cards and anti-piracy clips joined onto the build**: `library add --file <clip> --name <NAME> --kind head-ident|tail-ident|rating-card|anti-piracy` copies media into a managed folder under the XDG data dir with an index recording what a build reads off it (raster, running time, whether it carries sound), `library list` prints what is there and `library remove --name` drops an item and the copy that came with it. `create --head-item NAME` and `--tail-item NAME`, both repeatable and joined in the order given, turn those items into reels of their own: head items are the CPL's first reels, tail items its last, and the feature's essence and reels are untouched. An item is conformed to the job at build time rather than at import, so one 30 fps 1920x1080 ident serves a 24 fps 2K build and a 25 fps 4K one. It is fitted onto the feature's coded raster with the container as the active area, decoded through the job's own `fps` filter, encoded at the feature's bit rate through the same DCI transform, and its sound is panned into the same lanes at the same sample rate and cut to exactly the reel's length, filled with silence for an item that carries none and for one whose sound runs short of its picture. A still is held for the duration given at import and costs one encode, the trick `--still-length` already uses. Subtitle and caption tracks stay on the feature's reels and never extend into an item's. FFOC and LFOC now describe the composition rather than the feature, so a head ident carries the first-frame marker, and `--marker` is refused with items joined on as it already is for a split composition. So are 3D, Atmos, `--hdr-dci` and `--versions`, none of which an item reel has a place for. Reel splitting is fine: the feature's reels split as before and the items sit either side. In the GUI it is an Ident Library panel with an import button, a kind select and two lists, Head and Tail, that items are dragged into and reordered in
- **A container choice fits the picture** (GUI): picking 2K Flat/Scope/Full or a 4K container scales the source onto that DCI raster with the container as the active area, letterboxed unless Fill container is ticked. Before, an untouched Fill box left the source at its own size and the build was refused for declaring an active area the frames did not have.
- **Where the time inside an encode went**: the job log's `[TIMING] encode took` line is followed by `[TIMING] encode breakdown: decoder wait 12s, frame prep 30s, j2k 4m10s, write 8s`, read off the four cumulative phase clocks postkit's `PipelineProgress` now carries. Frame prep and j2k are summed over the encoder threads, so either can come out longer than the encode's own clock. `create` prints the same four figures after the frame count it already logs. A held still and an image sequence handed straight to grk_compress time nothing, and the line is left out there rather than printed as four zeros
- **Sound level in the QC report**: `report` gains a Sound level section listing every sound track file of the package with its Leq(m) (ISO 21727, CCIR 468 weighted, measured through postkit's `loudness::measure_leq_m`), the limit for the composition's `<ContentKind>` and a pass or fail against it. Advertisements are held to 82 dB and trailers to 85 dB, both stated inline with where the numbers come from; a feature is shown against the 85 dB reference level and marked not applicable, as is any other content kind. An encrypted sound track is listed and skipped with the reason instead of being measured through a key the report does not have
- **`--encrypt` encrypts every essence**: the subtitle, closed-caption and Atmos tracks are now AES-128 encrypted at wrap time alongside picture and sound, each with its own content key. The CPL declares a `<KeyId>` on every asset block including `AuxData`, the keys file carries all of them, and the KDM `kdm` builds from it lists one key per essence with its ST 430-1 type: MDIK for picture, MDAK for sound, MDSK for timed text and MDEK for aux data, the same spellings libdcp and DCP-o-matic write. `--encrypt` used to refuse a package carrying any of those three tracks rather than ship it in the clear beside encrypted picture and sound, so an encrypted subtitled package could not be built at all and one built without the track failed a validator's partial-encryption rule
- **The crop and the subtitle tracks in the preview**: opening the preview on a reel's picture draws the crop the Source picture panel holds over the frame and loads that reel's subtitle file and the closed-caption file as the two subtitle tracks, so the Crop, Sub and CC buttons in the preview header have something to show. The crop follows the four fields as they are typed and the Auto-crop button as it fills them. mpv renders only SRT, ASS/SSA and WebVTT, so anything else is written out as SRT under the app cache folder first, DCST and Interop XML through `subtitle_extract` and PAC, MKS/MKV, FCPXML and Interop PNG through the same `load_styled_cues` the create path reads cues with. Previewing a built DCP reads both tracks back out of the package instead, cues placed on the composition timeline, and draws no crop because the pictures already carry it. A file the preview cannot read leaves its button inert with the reason in the status bar rather than stopping playback
- **Picture essence read for the QC report**: `report` runs the verify with `check_picture_details` and `scan_every_frame` on, where `verify` leaves the frame scan off and stays fast, so the report's Info rows carry dcpdoctor's codestream forensics line beside the measured picture bitrate
- **Packaged channel count**: `create --audio-channels 2|6|8|16` fills the sound track with silent channels up to the count asked for, so a stereo source ships in a 16-channel container without being upmixed to 5.1 first. Without the flag nothing changes: a 5.1 source is widened to 16 and every other source is packaged at its own width. A source carrying more channels than the count is refused before the encode and again at wrap time, naming both counts and pointing at `--audio-map` to fold channels. The labels follow the content rather than the container, so a stereo track filled to 16 carries `20/L,R,-,...` in the CPL's MainSoundConfiguration and stereo MCA labels in the sound MXF, where the fill channels used to be claimed as a 5.1 mix they carry nothing of. The "fewer than 6 channels" hint now names the flag that fixes it, and the GUI create panel has a Packaged channels select beside the upmix one
- **Preview QC controls** (guikit): the embedded preview's header gained a safe-area box (95% or 90%), an aspect mask (1.85, 1.90, 2.39), a centre cross, a thirds grid, a decode-scale select (Full, Half, Quarter, native to J2K through the decoder's `lowres`) and a HUD reading frame, fps, buffer depth and dropped frames. Shared with imfwizard through the guikit submodule.
- **Post-build Play / Inspect / Reveal**: a finished build shows the three buttons beside the progress bar, so the new DCP can be acted on from where the build was watched. Play opens it in the embedded preview through guikit's `previewDcp`. Inspect switches to the Verify view, points it at the output folder and runs the same verification the Validate button runs, calling that code rather than a second copy of it. Reveal opens the output folder in the file manager. Starting another build clears the row, so a cancelled or failed build never leaves buttons pointing at a package that was not written
- **Per-stage timings in the job log**: `run_job` clocks preflight, encode, audio, packaging and validation, and writes each as `[TIMING] <stage> took <m>m<s>s` next to that stage's own `[ENCODE]`, `[PACKAGE]` and `[VALIDATE]` lines, with a `[TIMING] total` at the end. The progress event is unchanged: its `elapsed_secs` already carries the encode's own clock from postkit, and the breakdown inside an encode (colour convert against frame prep against the J2K encode) would need a wider payload from postkit, recorded in DESIGN_TODO
- **The encode runs at the rate it is given**: postkit's encode seams now take a rational `FrameRate` rather than whole frames per second, so a fractional rate reaches ffmpeg's `fps` filter as `24000/1001` instead of `24`. DCP edit rates are whole numbers (SMPTE 428-11 / 429-13 define no 1001-based rate), so `create --frame-rate` and the GUI's Frame Rate menu are unchanged and every seam here passes `FrameRate::whole`. A 23.976 source packaged at 24 fps is still the deliberate speed-up it always was, with the 1000/1001 audio pull-up that goes with it
- **A pre-build check, so a job that cannot be packaged fails in a second** — every refusal `create` can make now fires before the encode, from one shared check over one description of the job. Four of them used to wait for the wrap, an hour of J2K later: a container larger than the frames the encoder produces, a sound sample rate that is not a whole number of samples per frame, an Atmos track whose file count does not match the picture, and a `--subtitle` or `--ccap` file the packager cannot read. So did the refusals a split composition makes (3D, Atmos, `--hdr-dci`, markers), the encrypted-package track check, and the `--audio-map` parse. `create --check` runs the whole check plus the hints and stops, encoding nothing and writing nothing under `--output`
- **Hints before you build** — advisory findings gathered before the encode, from DCP-o-matic's projector-facing list: an Interop package, a sound track with fewer than 6 channels or a count that is neither 8 nor 16, the experimental stereo upmix, Scope content letter-boxed in a Flat container (and the pillar-boxed and unusual-container cases), a video bit rate at or above 245 Mbps, 25/30/48/50/60 fps, 4K 3D, a source-to-DCP speed change that shifts the sound's pitch, audio peaking above -3 dBTP, sound with no language, a SMPTE feature with no FFEC and FFMC markers, and the subtitle and caption rules (first cue before 4 seconds, cues under 15 frames, gaps under 2 frames, more than 3 lines, lines over 52 or 79 characters, caption lines over 32, overlapping Interop captions). Nothing here refuses a build. The CLI prints them before the encode, and the GUI shows a "Before you build" dialog with Build anyway and Go back, silenced from the dialog or the Settings pref "Show hints before building" and still written to the job log
- **Burn-in during the encode** — `create --burn-subtitle <file>` renders the cues into the picture as it encodes, one decode and one encode, instead of the transcode-then-encode the standalone `burnin` command costs. It takes the same inputs `--subtitle` does (SRT, ASS/SSA, PAC, MKS/MKV, FCPXML, Interop DCSubtitle with PNGs), and works on every input shape that encodes: a video, an image sequence (which reaches the frame path through ffmpeg's concat demuxer) and a held still, which encodes once per cue change instead of once per frame. `--burn-subtitle-font <ttf/otf>` picks the face; without one the system fonts are used, and a machine with no font is an error rather than a blank picture. Burnt-in text is part of the image, so it registers no timed-text track, and passing the same file to both `--burn-subtitle` and `--subtitle` is refused. So is burning onto frames that are already X'Y'Z' (`--source-colourspace xyz`, `--hdr-already-pq`, `--hdr-to-dci-lut`), where display-RGB text would land in the wrong colour space, and onto a J2K directory, where nothing decodes. Also on the GUI create panel
- **Subtitle appearance**: `create` now decides how subtitles look, burnt in or packaged. For a burn: `--burn-font-size` (percent of the frame height), `--burn-colour`, `--burn-effect none|outline|shadow`, `--burn-effect-colour`, `--burn-outline-width` (percent of the text height), `--burn-line-height` (multiple of the text height), `--burn-margin` (percent of the frame height), `--burn-x-scale`, `--burn-y-scale`, `--burn-fade-up` and `--burn-fade-down`. For the packaged timed-text track: `--subtitle-font-size` (points), `--subtitle-colour`, `--subtitle-effect`, `--subtitle-effect-colour`, `--subtitle-fade-up` and `--subtitle-fade-down`, which write the ST 428-7 `Font` attributes and the per-cue fades, an outline spelled `border` as the standard spells it and a fade rounded to whole frames at the edit rate. Anything left unnamed keeps the value it always had, so an existing command line produces the same package. An appearance flag given without the track it styles is refused by name, `--ccap` keeps the default appearance, and colours are written `RRGGBB` or `RRGGBBAA`. Both sets are on the GUI create panel, apart from the two burn-in scales
- **Window state restore** — the GUI reopens with the size, position and maximized state it was closed with (tauri-plugin-window-state)
- **Composition identity in the CPL** — `create` now writes the `AnnotationText` Bv2.1 requires (equal to the content title, on both CPL and PKL), a `VersionNumber` in the CompositionMetadataAsset, and a `<Hash>` on every reel asset, which some servers check instead of the PKL's. Our own validator flagged all four on our own output
- **ISDCF content titles**: `create --isdcf-name` rebuilds the title to the ISDCF naming convention from what the package actually carries, so `--title "My Film"` on a stereo flat feature comes out `MyFilm_FTR-1_F_EN-XX_20_2K_ABC_20260816_SMPTE_OV`. `--audio-lang`, `--rating AGENCY=LABEL`, `--content-version`, `--studio`, `--territory-type`, `--isdcf-date`, `--temp-version`, `--pre-release`, `--red-band`, `--two-d-version-of-three-d` and `--version-file` feed the name, and the metadata among them lands in the CPL whether or not a name is built from it. The channel ladder is read from the packaged sound, so the name is built after the audio is prepared, and burnt-in subtitles are spelled in lower case where an open track is upper. `--output` is untouched. In the GUI it is a Settings toggle with a live preview under the title, plus a Naming and metadata fieldset
- **Ratings and content version in the CPL**: `create --rating` fills the ST 429-7 `RatingList` and the first `create --content-version` becomes the `ContentVersion` LabelText, both of which every created CPL previously left empty
- **ST 429-16 composition metadata** — `create --release-territory/--version-number/--chain/--distributor/--facility/--luminance`. A numeric territory declares the UN M.49 scope, without which readers measure it against the RFC 5646 region grammar and reject it
- `create-multi --container-dims`, matching `create`
- **KDM formulation and forensic marking** — `kdm`, `kdm-batch` and `kdm-rewrap` take `--formulation` (the four ISDCF Doc 5 spellings), `-p/--disable-forensic-marking-picture` and `-a/--disable-forensic-marking-audio [CHANNEL]`, which press and festival screenings are routinely ordered with. Omitting `--formulation` still derives it from whether `--device-cert` was given, so nothing changes for a caller who does not care. `kdm-batch` refuses a device-listing formulation up front, since a batch spans cinemas and carries no device list to name
- **Audio delay** — `create --audio-delay <ms>` shifts the sound against the picture, positive later and negative earlier. The running time is unchanged, so the shift is made up with silence at the other end and the sound still matches the picture duration the CPL declares; a delay at least as long as the programme is refused, naming both durations
- **Trim** — `create --trim-start`/`--trim-end` (`48f`/`2s`) cut the head and tail off the source. Picture, sound and subtitles move together: cues slide back by the head trim, a cue wholly outside the kept range is dropped and one straddling a boundary is clamped. Trim runs before padding, so `--trim-start 2s --pad-head 1s` drops two seconds and then prepends one. A trim that leaves nothing is refused
- **Still images** — `create --video card.png --still-length 5s` packages a single image held for a duration. The image is encoded once and its codestream linked for every frame, so a two-minute card costs one encode. A still without a length, or a length without a still, is refused
- **Source colour space** — `create --source-colourspace <rec709|p3|rec2020|xyz>` declares what the source carries. `rec709` (the default, byte-identical to before) leaves the compressor doing the DCI X'Y'Z' transform, `xyz` compresses untransformed, and `p3` and `rec2020` are converted frame by frame during the encode with the compressor's own transform off. ACES, ACEScg and LogC are refused rather than approximated: they are scene-referred or log, so only a 3D LUT (`--hdr-to-dci-lut`) converts them. A colour space other than the default is also refused for J2K input, where the picture is already encoded and no transform can run
- **Gain and fades** — `create --audio-gain` in dB, `--audio-fade-in/--audio-fade-out` and `--video-fade-in/--video-fade-out` in seconds. All four keep the running time the same, so the sound still matches the picture duration the CPL declares; a fade longer than the programme is refused
- **CPL markers** — every created composition now carries a ST 429-7 `MainMarkers` asset in reel 1 (Bv2.1 expects one), with FFOC/LFOC by default. `create --marker LABEL=timecode` (repeatable) places any of the ten defined markers, e.g. the FFEC/FFMC distributors ask for; the offsets are validated against the composition length. Previously the `markers` subcommand printed a MarkerList nothing read

### Fixed
- **`decrypt` and `transcode-dcp` wrote a CPL with no CompositionMetadataAsset**: both rebuild the CPL around the sound MXF the source package ships, so they now read that package's `MainSoundConfiguration` and `MainSoundSampleRate` and declare the same layout, where they used to declare none and leave dcpdoctor reporting `missing_required_element` on output that was otherwise clean. An Interop source carries no such block and its output still has none
- **A build with an empty Sound slot shipped with no sound at all**: the GUI's audio chain now begins by extracting the picture source's own audio track when no sound file is named, so an mp4 that carries sound packages that sound, with the map, upmix, delay, loudness and pull-up steps applied to it exactly as they are to a named WAV. `create` has demuxed the source since it was written, and only the GUI threw away the audio in the file it was handed. With no audio anywhere, a SMPTE build now packages silence as long as the picture, 5.1 wide or as wide as `--audio-channels` asks, instead of leaving the composition with no sound MXF. That also gives the CPL its CompositionMetadataAsset (ST 429-16), which carries MainSoundConfiguration and so cannot be written for a package with no sound track, the block dcpdoctor warned about on every soundless SMPTE package we built. Interop is unchanged, picture only and with no metadata asset
- **The DCI bitrate cap is enforced on SDR encodes**: the GUI's encode now passes postkit the 250 Mbps per-frame byte budget (`dci_codestream_byte_cap`) whenever `--hdr-dci` is off, where it used to pass no cap at all and only HDR jobs were checked, and the `pipeline` subcommand encodes through the same in-process encoder with the same cap, so `GRK_COMPRESS_BIN` no longer affects it. Either way the run stops on the first codestream over the cap, naming the frame, instead of encoding the rest of the clip first. An over-budget frame used to ride silently into the package and surface as `j2k_bitrate_exceeded` at QC. The overshoot itself, up to 14 bytes a frame on dense content at the cap, is grok's rate reservation missing the first tile-part's SOT and SOD, fixed separately in grok
- **Closed captions were in the wrong namespace**: a SMPTE closed caption is now written `<tt:ClosedCaption xmlns:tt="http://www.smpte-ra.org/schemas/429-12/2008/TT">` with a `<tt:Language>`, which is what ST 429-12 declares and what the ISDCF Bv2.1 test DCP and libdcp both write. It used to be a `<MainClosedCaption>` in the CPL's own 429-7 namespace, where the reel AssetList takes nothing after MainSubtitle but a foreign-namespace element, so every captioned package we built carried a schema violation. The other children come from 429-7's TrackFileAssetType and are unchanged. Readers here take either spelling with or without a prefix
- **`decrypt` dropped the Atmos track and refused encrypted timed text**: since `--encrypt` started keying the subtitle, closed-caption and Atmos essence, an encrypted package carrying any of them could not be turned back into cleartext. `decrypt` now reads an encrypted timed-text MXF as its document plus every ancillary resource and rewraps it with the same asset id, document, duration and resource ids, and reads an Atmos MXF frame by frame and rewraps that with its own asset id, with the reel carrying the AuxData block back. The Atmos track used to be left out of the rebuilt reel entirely, encrypted or not, so a decrypted package silently lost it. A track whose KeyId no key covers fails loud naming the asset. `transcode-dcp` carries the same three tracks through the same two functions
- **One 23.976-to-24 conform for both front ends**: a 24000/1001 source packaged at 24 fps is read 1:1 and plays 0.1% faster, with the sound pulled up by the same 1000/1001, which is what DCP-o-matic does by default. `hfr::conform_source_to_dcp` is the one place that decides it and `hfr::audio_pull_up` the one place that runs it. The GUI used to hand the source to an `fps=24` filter with no input rate, so ffmpeg duplicated one frame in every 1001 and kept the running time, and it never pulled the sound up at all. `pipeline` did both of those and had no pull-up either. Both now set postkit's `read_source_at`, which reaches ffmpeg as an input `-r` before `-i`, so every source frame is packaged once. `create` already read the picture 1:1 and pulled the sound up; its inline ffmpeg step is now that shared function. The hints say what will happen before the build, in `create --check` and the GUI's dialog
- **The subtitle options stopped at the create path**: `create --versions`, `create-multi`, `create-vf` and every closed-caption track rendered their timed text under the default options, so `--subtitle-font` and the placement, RTL and wrap flags were inert there and a machine with no system sans face could not build any of them at all. All four now render with the options the job was given, `create-vf` takes a `--subtitle-font` of its own, and a caption track carries the font and the placement while keeping the default appearance, which is what `--ccap` is documented to do. The eight end-to-end tests that skipped themselves on a machine with no font now name the face in the repo and run everywhere
- **Reels without cues carried no subtitle**: `create --reel-length` and `create
  --versions` gave a reel none of the cues fell into no MainSubtitle at all, which
  dcpdoctor reports as `subtitle_missing_from_reel` because a composition with
  subtitles needs one on every reel. Every reel now carries a timed-text asset
  spanning it, and a reel with nothing to show carries the placeholder cue
  DCP-o-matic writes for the same case: a single space from the reel start, one
  second long, with the same embedded font and `LoadFont` as any text cue. ST
  428-7 has no document without a cue in it, which is why the placeholder is a cue
  rather than an empty `SubtitleList`. The wrap takes the reel's frame count as
  the essence duration instead of deriving it from the last cue, so
  IntrinsicDuration and Duration match the picture on every reel. Closed captions
  follow the same rule, since every reel has to carry the same number of them
- **Timed-text packaging was not conformant**: every package carrying a converted
  subtitle or caption track failed six of dcpdoctor's ST 429-5 / ST 428-7 checks, and
  libdcp's verifier reads the same rules. The MXF ResourceID was the track file's own
  asset id, where ST 429-5 wants the document's `<Id>` and wants the file, the
  document and the resource to be three different things. The document declared no
  `StartTime`, so a player had nothing saying the reel starts at zero. A `Font` named
  `font1` that no `LoadFont` introduced, because a track built without
  `--subtitle-font` embedded no font at all. The `IssueDate` carried a `+00:00`
  suffix Deluxe QC rejects, the root declared a second, unused namespace, and the
  reel's MainSubtitle carried no `<Hash>`, which some servers check instead of the
  PKL's. A text track now always embeds a font, the machine's sans-serif face when
  the caller names none, and refuses the build when the machine has none rather than
  packaging text nothing can draw. Rebuild any package with a subtitle or caption
  track
- **A failed `create` exited 0** — eighteen fatal errors logged and returned without a failing exit code, so a watch folder or script read the run as a success and shipped nothing. They now exit non-zero. `--container` is also resolved before the encode rather than after it, so a bad value fails in a second instead of after a full J2K pass
- **`create-multi` carried its own copy of the container table** — it skipped the dimension validation `create` applies and could drift from it. Both now resolve the container through one function
- **`decrypt` and `transcode-dcp` dropped a package's markers** — both re-author the CPL around the same composition, and the marker track was not carried over, so a marked package came out unmarked. Markers are now read back from the source CPL and rewritten, offsets unchanged
- **The CPL declared a geometry the essence did not have** — picture geometry came from the `--container` value or the 2K/4K preset, so an ordinary 1998x1080 flat master with no container flag was packaged with a CPL claiming 2048x1080. Every declaration now comes from the coded raster read back from the codestream: `MainPictureStoredArea` and `ScreenAspectRatio` describe the frames, `MainPictureActiveArea` carries the container (what a projector masks to), and a container larger than the frames is refused instead of declaring an active area the picture does not have
- **Encrypted DCPs shipped cleartext subtitles and Atmos** — picture and sound were encrypted at wrap time while the timed-text and Atmos tracks went out in the clear, with nothing in the package saying so. `--encrypt` now refuses a package carrying either track. Encrypting them needs the content key threaded through postkit's timed-text and Atmos wraps
- **`--twok` / `--fourk` misframed a source of another size** — the flags overwrote the encode raster with the container size while ffmpeg kept decoding at the source raster, so every frame of e.g. a 1998x1080 flat master was read misaligned and the CPL declared a size the J2K frames did not have. The mismatch is now refused up front, naming both rasters. Fitting the source automatically is still to come; use `convert` meanwhile
- **3D encoded at twice the requested bit rate** — `create --right-eye` encoded both eyes at the full `--video-bit-rate`, so the delivered stereoscopic track ran at double the requested rate (500 Mbps for `--video-bit-rate 250`) and could breach the DCI cap. The ceiling covers the whole stereoscopic track, so each eye now gets half the budget, as libdcp does

## [1.2.0] - 2026-08-13

### Added
- **Rebindable GUI keyboard shortcuts**: every shortcut now lives in one registry. Ctrl+K opens an overlay listing them by category, where clicking a shortcut captures a new key combination (Backspace or Delete unbinds, Escape cancels, a combination already in use is refused and names its owner). Per-shortcut and global reset buttons restore the defaults, and changes persist across restarts
- **KDM distribution** — cinema/screen database (`cinema add|list|remove|add-screen|remove-screen|search|import-flm`, no private keys stored), named validity templates (`kdm-template`, used via `kdm/kdm-batch --template`), generation history (`kdm-history`, metadata-only JSONL), FLM-x / SMPTE 430-7 import (`cinema import-flm`), email delivery (`kdm/kdm-batch --email-to --smtp-config`, one zipped email per cinema), and `kdm-batch --cinema/--screen/--cert-dir` recipient resolution. `cert-fetch --vendor --serial` downloads recipient certs from the credential-free public endpoints (dolby/doremi, qube)
- **`decrypt` subcommand** — turn an encrypted DCP into a cleartext DCP of the same reel structure. Content keys come from a KDM + recipient RSA key (`--kdm --recipient-key`) or the DCP's `KEYS.json` (`--keys`); a wrong key or an uncovered KeyId fails loud. Key material stays in memory only
- **`assemble` subcommand** — build one new OV composition (single CPL) whose reels are the input DCPs' reels in program order; essence is copied byte-identical and referenced by its existing UUIDs. Inputs must share standard/rate/resolution and must not be encrypted
- **`edit` subcommand** — rewrite a DCP's CPL metadata (title/annotation/content-kind/issuer) without re-wrapping essence, assigning a new CPL id and refreshing PKL/ASSETMAP atomically. Refuses encrypted DCPs
- **`create-multi` subcommand** — multi-composition package: one CPL per manifest entry, each with its own picture/sound/subtitle, over one shared PKL/ASSETMAP (contrast `create --versions`, several CPLs over shared essence)
- **Subtitle VF** — `create-vf --replace-subtitle`/`--add-subtitle REEL=PATH` (with `--subtitle-language`) wraps an SRT or SMPTE XML into a per-reel timed-text MXF; a subtitle-only VF references the OV picture/sound by id and ships only the new subtitle MXF
- **Explicit reel splits** — `create --split-at <tc>[,...]` (HH:MM:SS or HH:MM:SS:FF) and `create/pipeline --split-chapters` (source chapter marks via ffprobe) feed the same multi-reel path as `--reel-length`, rejecting any reel shorter than 1 second
- **Custom container** — `create --container <2k-scope|...>` and `create --container-dims WxH` (even, within the 2K/4K bound; threads into CPL ScreenAspectRatio and MainPicture stored/active area)
- **Head/tail padding** — `create --pad-head <dur> --pad-tail <dur>` (`48f`/`2s`) with sample-accurate silence; `--pad-color <RRGGBB>` fills pad frames with an sRGB colour (routed through the DCI X'Y'Z' transform) instead of black. Rejected loud when combined with reel-length/3D/Atmos or head-padding a supplied SMPTE subtitle XML
- **Input decode range** — `create/pipeline --input-range full|legal` forces the source's decode range, correcting wrong or absent range flags (re-decodes into a lossless FFV1 intermediate)
- **Disk writer** — `format-drive <target> --fs ext2|ext3 [--label] --yes [--image]` (refuses mounted targets) and `check-drive <target>` (report fs type + label, works unprivileged on image files)
- **Sign-language video** — `create --sign-language-video <file> --sign-language-lang <rfc5646>` (ISDCF Doc 13): VP9-packed into 288 KB PCM blocks on sound channel 15, labeled SLVS via MCA, with the ISDCF SignLanguageVideo ExtensionMetadata in the CPL
- **Create-time audio processing** — `create --upmix a|b` (stereo→5.1), `--loudness-target leqm=<db>|lufs=<v>` with `--true-peak-ceiling`, and filename channel auto-routing (a directory of mono `name_L.wav`/`_R`/... files). Standalone `crossfade --a --b -o --overlap` (equal-power) and `mid-side-decode -i -o --mid --side`
- **Encode QoL on `create`** — `--start-at HH:MM|RFC3339|+offset` (scheduled wall-clock start), `--resume` (reuse on-disk J2K frames after an interruption, survives restarts), average-fps ETA in progress output, `--shutdown-when-done` (power off after a clean encode)
- **Subtitle input formats + authoring** — `create --subtitle` accepts `.ass`/`.ssa`, `.pac`, `.mks`/`.mkv`, `.fcpxml` and Interop `DCSubtitle` XML with PNG bitmap subs (styling and per-cue alignment carried into the DCST). Placement (`--subtitle-halign/--subtitle-valign/--subtitle-vposition`), 3D depth (`--subtitle-zposition`), RTL (`--subtitle-rtl auto|on|off`), auto-wrap (`--subtitle-wrap <chars>`) and font embedding + subsetting (`--subtitle-font`, `--subtitle-no-subset`, cross-reel font dedup)
- **`subtitle-edit` subcommand** — edit a standalone subtitle file (any parsable format): `--list`, `--shift-ms`, or `--index N` with `--text`/`--set-start-ms`+`--set-end-ms`, written back as SRT
- **HDR source delivery** — `create --hdr-to-dci-lut <lut>` runs the LUT before J2K encode; `--allow-generic-hdr-tonemap` opts into FFmpeg tone mapping with a warning. APV source files decode through ffmpeg when the local build has the decoder
- **`subtitle-extract` subcommand** — export timed text from a DCP (or a bare subtitle asset) back to `.srt` (timing preserved) or `.txt` (text only), format chosen by output extension. Reads MXF-wrapped ST 428-7 resources via asdcplib and loose SMPTE/Interop XML, resolves subtitle assets through the CPL/ASSETMAP, and concatenates reels with their timeline offsets applied. GUI extraction panel added
- **Destination free-space check (DoM 3150)** — `create` and `copy` now fail early with a clear message when the required bytes (essence for create, source total for copy) exceed the free space on the destination filesystem, instead of running out mid-write. Cross-platform via `statvfs` (Unix) and `GetDiskFreeSpaceExW` (Windows)
- **CompositionMetadataAsset (Bv2.1)** — SMPTE CPLs now carry a ST 429-16 `CompositionMetadataAsset` in the first reel with `MainSoundConfiguration` (e.g. `51/L,R,C,LFE,Ls,Rs` with `-` padding for the silent fill channels), `MainSoundSampleRate`, `MainPictureStoredArea`/`ActiveArea`, `FullContentTitleText` and the Bv2.1 `ExtensionMetadata` marker. The sound configuration is derived from the packaged channel count, so validators no longer flag "0 channels but sound assets have N". Interop CPLs are unchanged. Verified: the asset validates against the ST 429-16 XSD and the whole CPL against ST 429-7 via xmllint
- **`ingest-package` subcommand** — metadata-only repackaging: scans a directory, reads each MXF's embedded asset UUID (asdcplib), and regenerates ASSETMAP/PKL/VOLINDEX covering every asset file present, reusing hashes from the old PKL where available. Fixes exported OV/VF folders (e.g. a Sony server's VF export) whose ASSETMAP/PKL omit hardlinked assets referenced by the CPL. Essence passes through untouched; the old ASSETMAP/PKL are replaced. Both SMPTE and Interop naming
- **Configurable subtitle position** — `subtitle-convert --vposition <percent>` (default 8) sets the bottom line's distance from the bottom of the screen
- **Stereoscopic 3D** — `create --right-eye <input>` (main input is the left eye) encodes both eyes at the same settings, wraps them into one ST 429-10 stereoscopic picture MXF (postkit `wrap_stereoscopic`) and emits the CPL `MainStereoscopicPicture` element (429-10/2008 namespace, EditRate at the composition rate, FrameRate doubled for interleaved L/R). Eye frame counts must match. Verified: a short 3D DCP passes `dcpdoctor validate` with 0 errors and the stereoscopic element validates against the clairmeta 429-10 XSD via xmllint
- **MCA channel labeling** — every PCM sound wrap now carries ST 429-12 / 377-4 MCA labels derived from the probed channel count (2.0 / 5.1 / 7.1). `create --hi-channel <n>` / `--vi-channel <n>` label a channel index as the standalone HI / VI-N accessibility track. Verified by reading the labels back out of the MXF with asdcplib (`mca_labels`)
- **Dolby Atmos aux track** — `create --atmos <file-or-dir>` wraps a Dolby Atmos / DCData bitstream (postkit `EssenceType::Atmos`) and registers it as a ST 429-18 `AuxData` element (Dolby `2012/AD` namespace, IAB data-essence UL) in the CPL/PKL/ASSETMAP. Verified: an Atmos DCP with a synthetic payload passes `dcpdoctor validate`; real-essence conformance needs real Atmos material
- **Interop KDM** — `kdm --format smpte|interop` (default smpte) and `kdm-batch --format`. Interop uses postkit's digicine ETM (134-byte key block). Verified: an Interop KDM carries the digicine namespace and verifies with xmlsec1. Legacy output, mark for real-gear validation before production use
- **`transcode-dcp` subcommand** — re-encode an existing DCP's picture essence to a lower bandwidth (`--video-bit-rate`, optional `--width`/`--height` rescale). Extracts each J2K frame from the picture MXF (asdcplib), decodes with grk_decompress, re-encodes with grok at the target ratio, rewraps, and emits a fresh CPL/PKL/ASSETMAP with correct hashes. Audio and subtitle tracks are copied unchanged; encrypted input is rejected
- **Reel splitting**: `create --reel-length <minutes>` splits the picture, audio (sample-accurate at the frame edge) and subtitles (DCST re-split and rebased per reel) into one MXF set per reel and emits a multi-reel CPL over a shared PKL/ASSETMAP; every reel is at least 1 second, a sub-second remainder merges into the previous reel. Absent the flag the single-reel path is unchanged
- **HFR validation**: legal DCP rates are 24/25/30/48/50/60/96/100/120 (SMPTE; Interop stays 24/25/30/48); 4K is capped at 30 fps. Illegal fps/resolution combos are rejected loudly before encoding; the GUI frame-rate menus offer exactly the legal set
- **Subtitle packaging** — `create --subtitle <srt> [--subtitle-language]` converts SRT to ST 428-7 DCST XML, wraps it as a timed-text MXF and registers the track in the reel/CPL/PKL/ASSETMAP
- **`export` subcommand** — ProRes/H.264/H.265/DNxHR/image-sequence export of a picture MXF (previously only reachable via the batch daemon)
- **`transcode --format` / `--bit-depth`** — wired the GUI transcode controls to the real backend
- **`watch --webhook-url`** — POST a JSON notification when a new DCP is detected

### Changed
- **The still hold, crop resolution, free-space check and kdm store helpers come from postkit**: `still` and the auto-crop/fill-crop/conflict logic of `source_picture` were near-copies of imfwizard's, drifted apart, and both now delegate to `postkit::still` and `postkit::picture_processing`. `free_space` moved to `postkit::free_space` unchanged, and the kdm store's atomic write and untrusted-cert parsing are `postkit::fs::write_atomic` and `postkit::certificate` now, leaving `store` as just the data-dir paths. Three behaviour changes ride along: passing two of `--crop-*`/`--auto-crop`/`--fill-crop` says "give only one of them", naming the flags, instead of "one or the other"; `--auto-crop` refuses a threshold outside 0..1 and a source that is all black at the threshold instead of cropping to nothing; and `--rotate`/`--flip` accept the union of the two wizards' spellings, adding `0` for no rotation.
- **`edit` is postkit's package edit**: the rewrite moved to `postkit::package_edit::edit_package`, which does the same job for an IMF composition, so a DCP and an IMP are retitled by one piece of code instead of two that can drift. `edit`'s flags, exit code and log lines are unchanged, as is the GUI's retitle. Four things now behave differently. Asking for a field the CPL does not carry is an error instead of a silent no-op, so `--issuer` on a CPL with no `<Issuer>` says so rather than reporting success over an unchanged document. A CPL that cannot be hashed is an error instead of a PKL entry written with an empty `<Hash>`. An ASSETMAP that does not list the composition is an error instead of a rewrite that leaves the package inconsistent. And `--output` copies subdirectories, where it used to copy only the files at the top of the package and quietly drop anything nested.
- **TMS upload lives in postkit**: the config type, the `TmsTransport` trait, both transports and the upload itself moved to `postkit::tms` behind a feature, so imfwizard can deliver an IMP the same way. Nothing about `tms` or `create --upload-to-tms` changes: the config file is still `~/.config/dcpwizard/tms.toml` unless `--tms-config` points elsewhere, and reading it stays here because the path carries this app's name.
- **Encode bandwidth** — the GUI now maps the target Mbps to the J2K compression ratio (was hardcoded)
- **`colour --target xyz`** — routes through the real DCDM Rec.709/P3/Rec.2020 → X'Y'Z' transform (fails loud on an unsupported source)
- **PCM wrap** — rejects non-DCP audio sample rates (48/96 kHz only) instead of mislabeling
- **KDM validity** — duration-based end times keep the start's UTC offset
- **GUI resolution** — scope/flat/full map to the correct container dimensions; content kind `episode` maps to a real ContentKind
- **Subtitle timecodes** — SMPTE DCST now emits frame-based `HH:MM:SS:FF` (schema-valid), not `HH:MM:SS.mmm`
- **Shared GUI frontend**: the preview player, keyboard shortcuts and base stylesheet now come from the PostPerfection/guikit submodule at `extern/guikit` instead of per-app copies, shared with imfwizard. `gui/src/style.css` keeps only the dcpwizard-specific rules, loaded after the base. Building the GUI from source now requires the submodules checked out (`git clone --recurse-submodules`, or `git submodule update --init`). No behaviour change

### Removed
- **DTS:X** — was silently mapped to the Atmos (IAB) essence UL, which is wrong for DTS:X. Removed the `MxfType::DtsX` variant and dropped DTS:X from the docs; blocked on a confirmed DataEssenceCoding UL (see DESIGN_TODO)
- **Dead scaffolding modules** — atmos.rs, audio.rs, stereo3d.rs, dtsx.rs (shelled out to a nonexistent `asdcp-wrap`, zero callers; superseded by the real postkit-based 3D/Atmos/MCA wiring)
- **OpenJPEG encoder** — grok is now the only J2K encoder. Dropped the `create --encoder` flag and the openjpeg branch; the postkit dependency enables `grok-ffi` (not `openjpeg`). libgrokj2k must be discoverable by pkg-config at build time and loadable at runtime
- **KDM `--formulation`** — was inert (MessageType is fixed by ST 430-1); removed from CLI/config/docs
- **`verify --output .pdf`** — silently produced plain text; option dropped
- **Dead modules** — dcp_diff, plugin, preferences, geometry, and the prores re-export shim (zero callers)

### Added
- **Signing on the rest of the packaging commands** — `assemble`, `create-vf`, `create-multi`, `combine` and `ingest-package` take `--signer-cert/--signer-key/--signer-chain` like `create` does. Each signs a CPL before anything hashes it into the packing list. `combine` and `ingest-package` sign only the PKL they generate, since they hash the CPLs rather than rewriting them, so a signature a CPL already carries stays valid. `create-vf` signs after the supplemental marker is written, not before, or the marker would invalidate it. `conform` takes them too, and signs whichever package it delivers: the per-reel DCP when a single reel is moved straight out, the assembled CPL and PKL when it merges reels

### Fixed
- **Signer certificates were missing Basic Constraints and Key Usage** (via postkit) — every chain from `certificate chain` had a bare leaf, which ST 430-2 requires to carry both, so validators rejected packages signed with it. Regenerate any chain generated earlier
- **`edit` no longer leaves a stale signature** — editing a signed DCP rewrote the CPL, PKL and ASSETMAP but kept their `ds:Signature`, so the output verified as tampered (dcpdoctor `signature_invalid`). `edit` now drops the signature from every document it rewrites, and warns which ones lost it. The package comes out unsigned rather than falsely signed. Re-sign it afterwards if it has to stay signed
- **Subtitle vertical position** — SMPTE and Interop subtitle generators anchored the block at the top (Vposition 85 with Valign="bottom") so subtitles rendered near the top of the screen. The bottom line now sits at 8% from the bottom with lines stacked upward (a two-line cue renders at 15% and 8%)
- **GUI "Show in Files"** — uses the tauri opener plugin (`revealItemInDir`); the shell `open` call only accepted URLs
- **Copy-to-drive verify** — flushes to the device and drops the page cache before reading back, so verification is real
- **FFOC marker value** — default markers now emit FFOC = 1 (was 0). libdcp's Bv2.1 verifier raises `INCORRECT_FFOC` unless FFOC == 1; LFOC stays at the last frame
